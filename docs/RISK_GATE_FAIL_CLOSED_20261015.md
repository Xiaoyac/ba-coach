# 风险检查前置与失败阻断

## 行为

- 风险检查明确通过后，才允许承接回复和 Router 开始，随后进入对应模块的主回复。
- 合法的风险阳性结果仍进入现有危机处理分支。
- 风险检查超时、调用异常、空返回、无法解析、无效状态值、被截断的结果，均不能视为检查通过。配置关闭检查也不会放行普通对话。
- 检查失败只返回：“本次安全检查未能完成，暂时无法继续对话。请稍后重试。”
- 失败分支不调用承接、模块 Router、普通主模型、检索或 PA 工具，不进行模块推进、事实抽取或总结；保留原模块和运行时记忆。
- 失败提示作为系统生成的消息保存，刷新后仍可见；后续请求重新执行风险检查。

## 实现

| 文件 | 修改 |
| --- | --- |
| `backend/app/graph/nodes.py` | 明确风险检查状态与有效结果条件；增加只保存提示文本的失败分支，直接结束图执行；调用异常保存失败遥测。 |
| `backend/app/graph/builder.py` | 风险失败进入独立终止分支，绕过普通回复及后台业务处理节点。 |
| `backend/app/pre_reply_routing.py` | 只有明确通过的检查结果才能进入普通 Router。 |
| `backend/app/provisional_reply.py` | 承接启动依赖明确的检查通过状态，不再将“存在耗时字段”当作通过；检查失败或被关闭时跳过承接。 |
