# PA 卡片原生工具调用实验

状态：本地实验功能，默认关闭；未部署、未提交或推送本次修改。

## 范围和调用顺序

只对正常 V2 会话的 M2、M4 启用。M1、M3、危机会话、沙盒和强制模块请求沿用已有路径。仍使用数据库中实际生效的全局和模块 Prompt，不修改干预内容或整段替换回复。

1. Router 读取当前输入；在启用工具的 M2/M4 轮次，卡片写入和正式迁移交给本轮工具事务。
2. 主模型先以原生 `tool_choice` 调用 `get_pa_card`，读取已拥有的卡片、版本及消息来源。
3. 模型选择操作，或明确调用 `continue_pa_conversation` 表示本轮无需改卡。不是从普通回答里的“已保存”推断写入。
4. 后台校验实际用户消息边界、账户、版本、证据来源和已有确认规则，事务提交后返回真实结果。
5. 展示卡片和 M4 总结使用工具返回的实际产物。其他自然回复继续流式输出；工具决策消息不冒充最终对话。
6. M2 确认成功后使用生效的 M3 Prompt 继续回应。M4 仅结束本轮，保持/调整/替换仍留给下一轮 M2。
7. 本轮不再执行旧的回复后卡片抽取，避免两条写入链路竞争。真实助手消息落库后，才建立“用户看过这一版卡片”的确认标记。

## 工具

| 工具 | 作用 |
| --- | --- |
| `get_pa_card` | 查询当前草稿、有效确认计划、历史核心、状态版本和消息来源 |
| `save_pa_card` | 保存有来源的 M2 草稿；支持已有业务规则中的保持、替换和次要活动 |
| `present_pa_card` | 显示实际完整草稿；显示不等于确认 |
| `confirm_pa_card` | 确认用户实际看过并同意的版本，提交成功后进入 M3 |
| `save_pa_review` | 保存 M4 事实与证据，不自动结束 |
| `close_pa_card` | 满足既有收尾条件后关闭本次尝试，下一轮目标选择留给 M2 |
| `continue_pa_conversation` | 不写卡片，继续当前模块对话 |

原生协议为 `tools`、`assistant.tool_calls`、`tool_call_id`、`role=tool`。当前接入 DeepSeek 兼容接口和 Doubao 兼容接口；不是 MCP，也不从可见文本中解析伪工具命令。

## 启用和回退

默认配置：

```dotenv
PA_CARD_TOOLS_ENABLED=false
PA_CARD_TOOL_MAX_ROUNDS=5
PA_CARD_TOOL_TIMEOUT_SECONDS=90
```

仅在独立测试数据库或另行批准的试验环境中将开关改成 `true`，重启后端后生效。原有模型名、API 地址和密钥配置不变。最多五轮工具决策，另加一次只生成回复的请求；总预算 90 秒。重试仍可能增加延迟，不承诺比旧路径快。

关闭开关恢复原生成/抽取路径；关闭不会撤销已经合法提交的卡片。无需新建数据库表或运行迁移，事务日志使用已有 `ai_decision_logs`。

## 诊断

`main_generation` 事件中的 `pa_tools` 包含每次实际请求的 system/messages/tools/tool_choice、请求 ID、耗时、用量、工具结果和错误。管理员的请求记录会逐条列出工具后续调用，不再只显示最后一个 Request ID。公开分享的权限和载荷契约未在本任务中修改。

不能只看回复文字判定成功：必须核对工具的 `status`、最终数据库卡片和周期状态。工具返回拒绝时不能表示用户“没回答”，更不能视为保存成功。

## 当前适用边界

这是可比较的实验实现，不是已经证明优于旧版的生产方案。复用既有字段契约有利于保护历史数据，却也让工具参数较复杂。模型仍可能漏填、错误调用、选择不写入，或在工具失败后说出与数据库不一致的话；本次没有引入固定 coaching 文案替换或修改干预流程来掩盖这些失败。

只有业务事务的校验和提交是确定性的。选择哪个工具、怎样表达以及是否误报成功仍需实测。应先看实际回放，再决定是否简化工具参数、继续灰度或放弃该方案。
