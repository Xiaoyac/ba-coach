# 目标卡后台写入与主回复并行（2026-10-14）

状态：已部署至 `20261014T145351Z`，前后端服务和公开静态资源已核对。没有修改管理员保存的提示词或数据库结构。部署和管理员抽屉验收见 `ADMIN_EXECUTION_DRAWER_20261014.md`。

## 改动后的流程

```text
风险判断 → Router
                ├─ 独立目标卡后台模型 → 工具校验 → 数据库写入
                └─ 检索／知识中介 → 主回复模型 → 正文输出及保存

目标卡需要附加到对话的展示内容：绑定本轮已保存的回复，再发布。
承接仍使用原来的独立并行流程。
```

原实现的 `prepare_pa_reply_node` 会等待目标卡模型和工具循环全部结束。现在该节点只启动后台任务并立即返回，目标卡与检索、主回复生成重叠执行；不是等正文保存后再开始写卡。

卡片数据库写入可以早于正文完成。只有需要绑定本轮回复的卡片展示和会话缓存同步，要等待该回复的保存边界。这不会反向阻塞主回复生成。

## 写入与正文的职责

- 主回复模型不接收目标卡原生工具，继续使用既有前台约束：依据真实事实交流，不提前声称本轮卡片已保存、确认、删除或结束。
- 后台沿用原有目标卡工具、版本校验、用户证据和确认契约。
- 同一轮后台任务只启动一次；正文保存后的旧调度入口不会重复启动或取消已经在执行的任务。
- 后台允许从“本轮用户消息是最新消息”跨到“本轮紧邻的回复已保存”，但不接受其他用户、更新的用户消息、额外助手消息或位置不匹配的回复。
- 后台证据仍截断在本轮用户消息，不能把刚生成的正文当作用户意愿或确认依据。
- 主回复完成时重新读取已提交的业务状态，避免旧的内存快照覆盖后台刚保存或确认的卡片。
- 用户在生成期间明确停止时，取消后台任务；已经提交成功的写入不会被描述为自动回滚。新用户消息到来后，旧任务的后续操作会被边界检查拒绝。
- 后台失败不会阻塞或丢弃已经生成的正文，失败和来源消息保留在独立目标卡事件中。
- 语义确认的模型调用放在短数据库事务之外，避免等待模型时持有写锁，拖住主回复保存。

范围说明：上述并行化覆盖自然语言对话触发的目标卡／PA 工具处理（启用时的模块二和模块四）。用户点击结构化确认按钮仍沿用既有、针对确定卡片版本的直接事务确认流程；这类明确按钮操作不需要先交给模型重新判断。

## 可观测性

目标卡事件记录 `timing=parallel_with_main_reply`、相对本轮开始的 `start_ms`、`tools_duration_ms`、`publish_wait_ms` 和 `user_message_id`。

工具处理时间和等待正文后的展示发布时间分开记录，避免再次把后台等待当成主回复前置耗时。

## 验证

214 项相关测试通过（跨两次最终验证合计去重），包含 13 项新增并发测试：

1. 人为阻塞后台模型，主回复仍能完成。
2. 后台模型失败，主回复仍正常完成且内容保留。
3. 人为保持正文未结束，后台仍能先将卡片写入数据库。
4. 新用户消息在正文保存前到来，旧后台不能继续写入。
5. 新用户消息在正文保存后到来，旧后台仍不能继续写入。
6. 显式停止生成会取消正在等待模型的后台任务。
7. 后台先完成，卡片展示随后正确绑定本轮回复。
8. 正文先完成，后台随后正确绑定并同步卡片展示。
9. 语义确认等待模型时没有打开的执行器数据库会话，正文仍能保存；后台随后完成合法确认。
10. 错误账号不能取得写入边界。
11. 额外助手消息不能被认作本轮回复。
12. 不相邻的回复不能被认作本轮回复。
13. 后台先确认并进入模块三后，正文旧的模块二快照不能覆盖已提交状态。

另外覆盖既有后台工具、原生工具、前置路由、目标卡交互、就绪校验、绑定确认等回归。

## 修改文件

- `backend/app/pa_reply_preparation.py`：改为只调度独立任务。
- `backend/app/pa_background.py`：提前启动、每轮去重、取消、展示发布与计时。
- `backend/app/pa_card_tools.py`：跨本轮回复保存边界，保留所有权与新消息失效校验；并行确认不持有数据库会话等待模型。
- `backend/app/graph/state.py`：保存本轮后台任务引用与来源用户消息 ID。
- `backend/app/graph/nodes.py`：保留后台职责约束，记录实际并行状态。
- `backend/app/graph/builder.py`：更新流程说明。
- `backend/tests/test_pa_parallel_reply.py`：新增并发及数据一致性测试。

部署候选版本的真实模型测试已观察到目标卡与主回复运行时间重叠。该测试用于验证并行机制，不是同条件的性能 A/B 测试，不能把此前目标卡平均 14.8 秒直接当成每轮已节省的时间。
