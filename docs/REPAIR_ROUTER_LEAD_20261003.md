# Router 默认模式、保存闭环与承接修复（2026-10-03）

普通用户仍为 `router_only + ack_deep + low`。Router 选择回复模块；独立业务事务确认目标/记录，不能把模块跳转或助手声称作为保存成功证据。

## 本轮变更

- 兼容已合入的后台 PA 工具架构。旧版未启用目标 UI/PA tools 的纯 Router 路径，完整且实际展示的版本可由紧随其后的用户确认提交；不把代码重新变成 Router 的完成门槛。
- 前台回复对保存声明核验真实事务回执。流式输出按完整句核验，安全句可先显示；可疑句最多进行一次有时限的自然语言修正，仍不一致则保留已显示内容并报错，不伪造成功、权限或按钮。
- 每日记录侧栏按钮仅在业务允许的 M3 提供，与实际弹窗入口一致；目标新增通过对话进行，不指导用户点击不存在的“新建/+”。
- 承接上限 80 改为 **150**，维持原计数语义：规范化后的 Python `len`，含标点与空格；自动补句号也计入。1–2 句规则保留，并非150个汉字之外可再加标点。
- 承接在历史加载且风险检查完成后启动，与 Router 并发，不等待 Router/检索的完整 system。仅使用本轮输入、历史和独立承接规范，不预判本轮模块、目标合格性或事务结果。风险分流不显示普通承接。
- 正文继续读取实际承接内容后续写，按承接、正文顺序显示，避免重复。没有改成两个互不知道内容的正文模型同时起跑。
- 承接使用已核实的模型标识 `kimi-k3`。Ark Coding 接口为 `https://ark.cn-beijing.volces.com/api/coding/v3`；协议为 `reasoning_effort=low`，不发送不支持的 `thinking`/`enable_thinking`。默认预算2048 tokens，包含隐藏思考及输出；8秒上限保留。未调用真实付费模型，本次HTTP协议检查用MockTransport。
- 保留过滤，增加 `rejection_reason`（空白/超长/结构化输出/提问/操作声称等）和 `context_wait_ms`，不新增被拒绝原文日志。超时、渠道错误仍有独立原因。

## 生产配置需要同步，尚未执行

当前生产显式配置的 Qwen 会覆盖源代码默认模型。发布本轮代码时必须同时：

1. `REPLY_LEAD_MODEL=kimi-k3`，`REPLY_LEAD_MAX_TOKENS=2048`。
2. 若复用当前已配置 K3 的 DeepSeek兼容 provider：`REPLY_LEAD_PROVIDER=deepseek`，清除旧的 `REPLY_LEAD_BASE_URL` 和 `REPLY_LEAD_API_KEY` 两个专用渠道覆盖。保留主渠道凭据。
3. 或把专用 lead base/key 改为真实 K3 渠道，三项一起配置，不能只把 Qwen endpoint 上的模型字符串改名。
4. 保持 `REPLY_LEAD_TIMEOUT_SECONDS=8`。核查所有实际加载的环境文件，避免较后文件恢复旧值。

新代码拒绝旧 Qwen 配置并记录渠道配置错误，不会静默继续调用 Qwen。生产迁移、重启/部署均未获本任务授权，未执行。
