# 承接回复与正文显示衔接（2026-10-14）

## 用户可见行为

- SSE 的 `lead` / `body` 阶段保留到前端消息状态；普通用户和管理员使用同一套显示逻辑。
- 承接首字从收到第一段非空承接起等待 1000 ms 后开始浮现，之后逐字间隔从约 280 ms 渐增到最多 500 ms（2026-10-15 调整）。收到新片段不会重置等待或播放计时，也不会把一次收到的整段直接显示出来。
- 首字等待期间如果正文已经到达，立即进入正常的快速衔接；停止/结束、减少动态效果或切到后台时直接释放已收到的文字。首字等待不延迟 SSE 接收或正文生成。
- 承接结尾的一个完整字符保留至正文到达或本轮停止/结束。正文到达后，剩余承接在约 240 ms 内接上，正文恢复常规逐字显示，不让承接动画阻塞正文数秒。
- 承接期间不显示两套“三个点”。显示轻量光标；整轮等待超过 20 秒仍未收到正文时，明确提示“正文仍在生成，可随时停止”。短文本无法无限持续输出，不伪造额外承接或完成进度。
- 停止/出错释放已经接收的承接；已保存历史直接显示。系统减少动态效果设置和后台标签页不强制播放动画。

## 实现边界

这是前端显示调度，不延迟模型调用，不修改原始 SSE 文本、提示词、模块路由、数据库内容或复制内容。

- `frontend/lib/api.ts`：临时消息阶段与承接长度类型。
- `frontend/components/ConversationWorkspace.tsx`：接收 SSE 时保留阶段，忽略纯分隔符对正文开始的影响。
- `frontend/lib/useStreamingText.ts`：跨分片保留计时、承接慢速浮现、正文到达后的限时衔接。
- `frontend/components/MessageRow.tsx`、`frontend/app/globals.css`：光标与长等待说明，避免已经有内容后仍显示普通加载点。
