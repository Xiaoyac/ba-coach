# M2 网页目标卡与部署记录（2026-10-03）

## 用户可见行为

- M2 的 PA 介绍、意愿讨论和无意愿时的价值探索保持原有模块流程。
- 进入核心或次要目标制定时，模型调用 `open_goal_card`，卡片才在聊天上方展开；进入 M2 本身不会弹卡。
- 用户可以只填写想到的信息，保留空项；AI 根据表单、历史对话及现有计划讨论活动性质、近期安排和难度。
- 用户要求不再细化时暂停并保留草稿；恢复需当前用户意愿，不能用旧意愿重新打开。
- 核心计划复用原有来源、版本、正式展示和用户确认机制；次要活动独立保存，不改核心周期。
- AI 审核通过并真实展示后，用户确认对应版本。提交成功后收起，说明目标保存在“我的目标”。

## 代码边界

- `backend/app/goal_card_workspace.py`：草稿、版本、字段、历史审计和次要目标档案。
- `backend/app/goal_card_interaction.py`：开卡、审核、暂停、次要卡确认及按钮来源绑定。
- `backend/app/pa_card_tools.py`、`pa_tool_loop.py`：按当前卡片阶段提供可调用工具，使用真实工具结果保存和确认；显式确认轮保护被点击的版本。
- `backend/app/graph/nodes.py`、`pre_reply_routing.py`：只在功能开启的 M2 使用上述工具；正式确认成功后才进入 M3。
- `backend/app/routes/program.py`、`routes/chat.py`：拥有者校验、草稿接口、并发锁和真实消息绑定。
- `database_v2_schema.py`、`v2_deletion.py`、`routes/admin_accounts.py`：新表及删除兼容。
- `frontend/components/GoalFormulationPanel.tsx`、`frontend/lib/goal-card.ts`：填写、保存、暂停、版本冲突及迟到响应处理。
- `Chat.tsx`、`ConversationWorkspace.tsx`、`GoalOverview.tsx`：顶部入口、聊天 metadata 和“我的目标”展示。

数据库管理员 Prompt 保持原值；启用时向实际主模型输入追加网页卡片交互协议。默认 `GOAL_CARD_UI_ENABLED=false`。该功能不需要开启独立的 `PA_CARD_TOOLS_ENABLED` M4 实验。

## 数据库与回滚

先运行 `backend/scripts/migrate_goal_cards_1003.py --expected-database <数据库名>` 检查，再加 `--apply` 创建空表。只新增 `goal_card_workspaces`，不改已有业务表或 Prompt。迁移会匹配现有父表 ID 字段编码；新表使用 `utf8mb4`，避免旧库 `utf8mb3` 默认编码造成外键不兼容。

优先回滚方式是保留新代码及数据，设置 `GOAL_CARD_UI_ENABLED=false` 并重启后端。新代码在关闭功能时仍包含账户和聊天删除兼容。已有卡片数据后，不应直接切回不认识新表外键的旧删除代码。
