# 目标卡并行与管理员运行状态抽屉

上线验收日期：2026-10-15。版本：`20261014T145351Z`。

## 已上线的行为

目标卡后台在风险判断和 Router 之后启动，与知识检索、主回复生成并行。主回复不等待目标卡模型的工具循环结束；卡片的数据库写入可以提前完成，附加到对话的正式展示仍绑定本轮回复的保存边界。

管理员在对话顶部点击“运行状态”（手机显示波形图标）打开右侧小抽屉，聊天工具栏收起时也能打开。抽屉显示当前模块、各环节的模型名称、运行状态和耗时，区分主回复流程与独立并行任务；可以跟随最新一轮，也可以选择最近 20 轮中的一轮。打开时约每 1.5 秒刷新，关闭后停止请求，页面隐藏时暂停刷新。

目前覆盖风险判断、Router、检索、重排、中介、上下文压缩、主回复、承接、目标卡后台、模块摘要、事实提取及对话归档的已启动或已记录阶段。可选环节没有执行时不会虚构排队状态。失败、取消、跳过和等待发布分别显示，检索失败后继续生成正文也不会显示成检索成功。

目标卡后台写入完成但正文还没保存时，会显示“等待发布”，并提示“工具处理结束，等待绑定本轮回复”。主模型仍显示运行中，避免把这段时间误算成目标卡模型还在生成。

## 权限和数据边界

- 前端入口仅管理员可见。
- 后端仍独立检查管理员角色和会话所有权：未登录 401、普通用户 403、管理员访问非本人会话 404。
- 状态接口仅投影状态、模型名、耗时及该会话的轮次短预览，不返回提示词、原始请求或思考文本。
- 实时状态是当前单 worker 服务内的有限内存记录，最多 512 轮、保留约两小时；历史从持久化执行事件回读。重启后不会把旧记录冒充为仍在运行。
- 没有修改数据库结构、管理员保存的提示词、模型选择或自动重试次数。

## 实际时间线

候选版本真实模型测试的一轮中，目标卡后台在本轮约第 9 秒开始，工具处理约 28.5 秒；主回复在约第 21.5 秒开始，两者明确重叠。

公网版本首轮验收中，目标卡后台约第 14.2 秒开始，工具处理约 29.0 秒；主回复约第 27.3 秒开始，主回复请求及其重试共持续约 134.9 秒。目标卡完成后等待正文保存再发布，等待约 120.2 秒。服务日志进一步确认，前两轮主回复都收到上游 429 限流，自动重试一次后成功保存。因此这些长等待不能归因于目标卡写入串行，也不能把请求总耗时全部称为模型生成耗时。

这不是同条件性能 A/B 测试，不能把原先目标卡的平均耗时直接当成每轮已经节省的时间。测试仍观察到检索约 12 秒后降级的情况；本次将其真实显示为失败，没有顺带改动检索策略。
