# 聊天超时、过载恢复与自然承接修复

日期：2026-10-12（北京时间）

## 已部署范围

版本：`20261012T073444Z`。原版本：`20261012T041927Z`。

本次从线上版本复制并应用 18 个运行文件的定向变更，未整体覆盖本地其他未部署改动。没有数据库结构迁移，没有修改管理员保存的提示词，也没有改动既有对话的回复模式、思考强度或干预目标。

## 修复结果

### 1. 主回复使用一致的超时策略

管理员的“现有回复”、管理员的“自然接话＋深度回复”、普通用户的主模型请求均使用 **180 秒总预算**。兼容模型 SDK 的读取超时也同步设置，避免外层允许等待、SDK 却提前退出。

过载退避和重试占用同一个预算，不会每次重新计时。前端统一使用 300 秒的请求上限，给风险筛查、路由、检索和保存留出时间；因此 180 秒指主模型阶段，不是点击发送到完成的全部时间。路由、知识中介等辅助任务仍保留各自较短的超时。

### 2. 明确过载时最多自动重试一次

当前 K3 使用的兼容模型接口在建立响应之前返回 HTTP 429 或 503 时，退避后重试一次。尊重有限的 Retry-After，重试仍受总预算约束。

不会自动重试额度不足、认证错误、参数错误，也不会在已开始接收回复流后重放请求。用户取消会中断等待和重试。重试次数、状态和请求标识写入日志/执行记录，便于后续排查。

### 3. 失败提示结束等待，提供明确恢复入口

- 正确识别 `ServerOverloaded`、`TooManyRequests`，显示过载提示。
- 超时、过载、连接中断等失败文案不再一直承诺“正在同步”。
- 已收到的问题出现“重新发送并生成回复”按钮，直接展开显示。
- 点击后先结束/核对上次请求，再检查是否已有完整回复。
- 若已经有完整回复，就读取已有结果；若仍未完成，由用户的这次点击明确重新发送，保留此前原文和部分回复。
- 后端拒绝重试已有完整回复、已有后续用户消息、不属于当前账号或文本不一致的旧问题。同一账号的同一对话同时只接受一个流式生成请求，防止重复点击/多标签页并发。
- 没有收到消息保存回执时，不直接自动重发，保留“放回输入框（不发送）”。
- 只保存了一段承接或半条回复，不再视为生成成功。刷新后也可以从当前对话的最新未完成问题恢复入口。

这里的手动恢复是**明确重新发送并生成一条新回复**，不是从模型中断的字节位置续写，也不会覆盖旧记录。

### 4. 自然承接被整段丢弃的问题

检查时最近 12 小时的 49 条承接记录中，只有 4 条通过；22 条因带问句被拒，9 条超长，1 条句子过多，13 条模型调用异常。约 8 秒的部分异常实际属于超时，但以前被记成笼统的模型错误。

本次改为：当输出仅因问句、超长或句子过多而被拒时，尝试保留开头已经完整、并通过原有校验的陈述句。不会截取半句话，不展示问句，不放宽 150 字限制，也保留风险筛查及禁止虚构保存/确认结果的检查。后续主回复读取的正是最终保留的承接。

承接等待预算由 8 秒调整为 **12 秒**；超时原因单独记录。已修正服务器旧配置的覆盖顺序，使线上实际值也为 12 秒。

自然承接仍只属于“自然接话＋深度回复”模式；没有自动把管理员旧模式切换过去。上游长期不可用时仍可能没有承接，此时继续主回复，不生成固定占位套话。

## 效果边界

本次解决系统内部的预算不一致、过载不重试、错误提示停留和承接过度丢弃；不能消除供应商持续过载。自动重试也失败时，会明确告知失败并保留恢复入口，而不是无限等待。真实验收只证明这些请求成功，不代表未来的服务可用率。

## 2026-10-12 追加：五次自动重试

- 首次调用失败后，最多自动重试 5 次（总调用上限为 6 次）；成功后立即停止重试。
- 主回复尚未接收流时，429/503 过载、连接失败和请求超时可以重试；余额、配额、鉴权和参数错误直接结束。已经接收的回复流不会自动重放。
- 每次调用仍为 180 秒上限，成功那次的连接等待与流式输出共用这 180 秒。六次调用加重试间隔的总预算为 1105 秒；网页总等待上限为 1230 秒，为前置处理和保存预留时间。可以随时停止。
- 前后端通过带本轮 generation_id 的 retry 事件同步状态；普通用户和管理员都显示“重新连接中(网络超时)”。恢复、失败、停止时结束提示；重试耗尽后保留原文和已有的手动恢复入口。
- 提示文字按产品要求统一；日志仍保留实际错误类型、状态码、重试次数和请求标识，不把过载记成网络超时。
- 自然承接仍使用已部署的 12 秒预算。路由、提示词、思考强度与用户数据未修改。

验证：157 项后端回归通过，包括第五次重试成功、六次调用均失败、取消、单次截止时间、流开始后不重放以及重试事件经过完整图和 HTTP 接口。前端真实 SSE 解析、普通用户/管理员提示静态渲染、类型检查通过。此次没有浏览器交互验收；线上验证结果见下方。

线上验收：已部署版本 `20261012T083834Z`。8 个运行文件与发布清单哈希一致，公网实际加载的前端资源包含新重试提示；后端与前端进程均运行于新版本。临时普通用户使用真实模型完成回复并保存，自然承接正常显示（约 6.61 秒可见），测试账号与对话已清理。五次故障重试通过受控测试验证，线上真实模型验收这轮未发生重试；没有向真实用户对话注入故障。

## 2026-10-14 追加：承接不阻塞主模型，Flash 关闭思考

承接模型改为 `deepseek-v4.1-flash`（服务端返回别名 `deepseek-v4-1-flash`），使用隔离客户端与 `thinking: {type: disabled}`，不带 `reasoning_effort` 或思考预算。复用已有兼容接口凭据；主回复仍是 K3，原有思考设置不变。承接保留 12 秒自身截止时间，但不再因此阻塞主模型。

主模型完成路由、检索和提示词准备时，同步判断承接状态：已完成则读取同一份开头继续生成；未完成则取消、记录 `main_ready_before_lead` 并立即独立生成正文。已取消的承接即使迟到返回也不会显示。主正文到达时，已有承接的逐字动画仍立即补齐，不延迟正文。
