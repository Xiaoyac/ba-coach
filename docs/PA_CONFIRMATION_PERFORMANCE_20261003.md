# PA 后台读卡与按钮确认性能修复

基础修复已于 2026-10-03 部署到 `20261003T065440Z`，提交 `cbb791f`。承接通过现有火山 Ark K3 provider；一次合成请求为52字、3.15秒，无生产业务写入。本文件描述随后新增的性能补丁，尚未发布，需单独发布批准。

## 业务行为

- `pa_background_loop` 由应用先执行真实 `get_pa_card`，将实际结果放入标准 assistant/tool 历史，省去模型选择首次查询的请求。所有权、消息边界和状态版本仍由原执行器验证；失败立即停止。冲突后的重新查询、参数修正和预算限制保留。请求预算只统计真实模型请求。
- 已落库的目标卡按钮动作，在风险检查通过后、Router 之前执行。必须匹配当前用户、会话、用户消息、卡片ID/版本、前一条真实助手展示、有效PA核验和客户端按钮文本。核心目标仍通过既有事务核验草稿指纹、完整字段与难度来源，成功后进入M3；次要目标不改变核心目标或模块。
- 版本/展示/消息变化、跨用户操作、暂停、写入失败或取消不会产生成功回执。写事务内重新检查按钮证据；真实工具回执可幂等重放。普通聊天没有结构化按钮事件时仍走原来的语义判断。
- 已处理的按钮不重复调度后台工具。仅已提交回执允许正文声称确认成功；正文失败后的已有回执恢复逻辑继续适用。
- 提交时立即更新数据库revision并发送已提交模块元数据，正文随后生成。既有目标卡组件在回复中每2秒轮询，可在正文结束前看到保存状态；本补丁没有更改前端交互或承诺毫秒级显示。
