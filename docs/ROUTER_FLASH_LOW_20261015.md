# Router 切换到 DeepSeek 4.1 Flash / low

## 范围

所有模块路由入口通过同一独立客户端发送请求：`deepseek-v4.1-flash`、`thinking.type=enabled`、`reasoning_effort=low`。主回复的思考开关不会把 Router 的 low 关闭。旧的只返回模块编号的入口、常规路由和管理员评估路径共用该入口。

保留原有 JSON 恢复机制：首轮因输出长度不足而失败时，使用同一个 DS Flash 模型进行一次关闭思考的限时恢复。原 K3 路由通道的有效最小输出预算 2048 保留。主回复、目标卡、检索以及模块摘要的模型配置不受影响。未改管理员提示词和模块提交规则。

## 调试详情

“请求记录”中的 Router 项可展开每次真实调用：

- 实际发送的模型、thinking、reasoning_effort、max_tokens 和完整消息输入。
- 实际返回的模型标识、独立思考内容、最终输出与完成原因。
- 每次调用独立的 Request ID、HTTP 状态和耗时；首次请求与恢复请求分开。

数据从隔离客户端的 HTTP 请求/响应捕获，保存到现有执行事件 JSON，再通过原有管理员且限会话所有者的接口读取。不会读取或输出 API Key、认证头。历史数据没有这些字段时保持原样，不补造 DS 模型记录。

主回复前的路由思考继续通过现有 SSE、保存及重载链路返回；前端已修正“回复完成后才路由”的过时提示。模型建议与数据库实际生效模块继续分别显示。

## 检查

59 项专项检查通过，覆盖真实序列化参数、两个调用入口、截断恢复、取消清理、参数/响应回读、鉴权及分享隐私。

扩大路由检查共 82 项，其中 48 项通过；另外 34 项在修改前源码中同样失败，失败名称集合完全一致，未引入新增失败。旧测试主要仍假定无需已确认计划即可进入执行模块，与现有线上约束不符。未为本次模型切换修改业务门槛。

前端类型检查及服务器生产构建通过。8 组桌面/手机管理员、普通用户和公开分享场景通过：新增字段可展开，页面无横向溢出，文本不会执行脚本，普通用户及旧分享不会请求私有调试接口。

候选版本真实对话：Router 发出的模型 `deepseek-v4.1-flash`，返回标识 `deepseek-v4-1-flash`，实际请求 thinking=enabled、reasoning_effort=low。一次调用约 2.734 秒，返回 179 字符独立思考；原始请求与结果已持久化并从管理员接口重新读取。对话回复成功保存并重载，临时账号和会话已清理。此为单次功能验收，不是性能均值。

证据目录：`.test-tmp/router-flash-low-1015/`。

部署排空补充：旧进程日志的开始/完成计数差一条。没有直接依据日志计数终止请求；确认超过 180 秒无模型/对话活动，并再次查询数据库确认最近两小时所有用户消息均已有对应助手保存行后，才继续切换。
